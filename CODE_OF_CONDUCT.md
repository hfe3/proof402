# Proof402 Code of Conduct

Proof402 is infrastructure for payment-enabled agent workflows, so public
collaboration must stay calm, precise, and safe for operators.

## Expected Behavior

- Be respectful and constructive in issues, pull requests, reviews, and release
  discussions.
- Keep feedback focused on reproducible behavior, security impact, API
  contracts, and documentation clarity.
- Use fake hashes, fake metadata, and redacted logs in public examples.
- Assume production operators need clear risk boundaries around payments,
  wallets, secrets, and deployment state.

## Unacceptable Behavior

- Harassment, personal attacks, threats, or discriminatory language.
- Publishing secrets, wallet material, payment headers, database URLs, CDP
  credentials, raw private payloads, or exploitable vulnerability details in
  public threads.
- Encouraging unauthorized payment attempts, settlement abuse, spam, or
  disruptive traffic against the public service.
- Misrepresenting Proof402 as legal notarization or as storage for private raw
  payloads.

## Security-Sensitive Reports

Do not post active vulnerabilities or exploit details publicly. Use GitHub
private vulnerability reporting when available, or follow `SECURITY.md`.

## Enforcement

Maintainers may edit or remove comments, issues, pull requests, or examples
that violate this policy. Repeated or serious violations may lead to blocked
participation in the repository.
